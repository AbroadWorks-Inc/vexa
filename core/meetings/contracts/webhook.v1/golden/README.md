# webhook.v1 goldens

Wire-shape fixtures, one per `$def`/case. Filename `<Shape>.<case>.json`; the prefix names the
`$def` the file must conform to (validated by `../validate.mjs`, run by `gate:schema`).

Subscription deliveries (§2.7):
- `MeetingEvent.meeting-completed.json` — the step `stopping` → `completed`: one `meeting.completed`
  event with `data.change`.
- `MeetingEvent.bot-failed.json` — the step `awaiting_admission` → `failed` (`bot.failed`).
- `MeetingEvent.bot-retry.json` — a bot lost in the call while its meeting is on: the step
  `active` → `requested` (`bot.retry`, the retry writer's output), `bot_joins_at` the new bot's
  time.
- `MeetingEvent.meeting-updated.json` — an event that changes no status: no `data.change`.
- `TestEvent.webhook-test.json` — a `webhook.test` send: only `data.subscription_id`.
- `SignatureHeaders.subscription.json` — the signed headers of `MeetingEvent.meeting-completed`
  (no `Authorization`).
- `SignatureHeaders.rotated.json` — the same during the 24h after a rotation, with
  `X-Webhook-Signature-Previous`.

Legacy deliveries (system hook, per-user `webhook_url`):
- `Envelope.meeting-completed.json` — a `meeting.completed` delivery (terminal success).
- `Envelope.bot-failed.json` — a `bot.failed` delivery carrying the `status_change` block (terminal
  failure).
- `SignatureHeaders.signed.json` — the signed headers with a per-user secret, `Authorization`
  alongside.

Every envelope golden and both subscription header goldens are the real emitters' output, checked
and regenerated by meeting-api's `tests/test_webhook_goldens.py` (`WEBHOOK_V1_GOLDENS_WRITE=1`);
they are never edited by hand. The subscription envelopes are the stored outbox bodies of the
status writer, the retry writer and the test writer, pretty-printed: re-serialised compactly with sorted keys, a
golden is exactly the body posted, and the header goldens sign `MeetingEvent.meeting-completed`
that way (dummy secrets `whsec_demo_secret` and `whsec_demo_previous_secret`, timestamp
`1790658761`).
